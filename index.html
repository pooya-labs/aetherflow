Architecture

Small boundaries. Strong guarantees.

The runtime stays transport-neutral. PostgreSQL owns durable execution state, while JetStream carries committed events between services.

Rust core & runtime

Typed workflow identities, DAG validation, bounded scheduling, handler registry, cancellation, and dependency outputs.

Durable PostgreSQL

Atomic claims, migrations with checksums, attempts, leases, fencing, transactional outbox, and inbox deduplication.

Event transport

NATS JetStream publisher and pull consumer with stable message IDs, broker acknowledgements, and retry handling.

Recovery & idempotency

Fresh-process lease recovery, duplicate suppression, lease renewal, and fencing against stale workers.

Reliability model

Failure is part of the design.

A lease is temporary permission to work, not proof that the previous process has stopped. Every boundary states what happens next.

Fenced ownership

Heartbeat and completion are guarded by worker identity, version, and monotonically increasing fencing tokens.

Restart recovery

A fresh worker can recover expired work from database state without relying on the old process's memory.

Transactional outbox

Events are published outside database transactions and acknowledged only after JetStream confirms storage.

Durable inbox

Logical duplicates are keyed by consumer and event ID. A repeated delivery does not re-run a completed handler.

Long-handler heartbeat

Active inbox leases are renewed and JetStream receives progress acknowledgements while a handler continues.

Honest delivery guarantees

Delivery is at-least-once, not magical exactly-once. External side effects still need idempotency or a shared transaction.
